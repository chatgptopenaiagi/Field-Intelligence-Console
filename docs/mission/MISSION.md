## 7. NETWORK SEMANTICS AND ENTITY MODEL

The key rule is:
SAVED GEOGRAPHIC ASSOCIATION IS NOT CURRENT PHYSICAL PRESENCE.

A VCF address means a record associates an entity with that address. It does not
prove present residence, ownership, current whereabouts, or that the record is
still accurate. No phone number alone establishes a street or current country.

Use UI wording such as:
"Saved contacts associated with this area"
"Saved work address on this street"
"Addresses in your contacts within 1 km"
Never label saved-address results "People here now".

Model people and organizations with stable local identifiers and optional:
- display/structured names, organization, role, user tags and notes;
- multiple typed phone numbers, email addresses and postal addresses;
- original values alongside normalized search representations;
- import source, source-record identifier and source ancestry;
- import time, source update time when supplied, user corrections;
- separate location associations and geocoding results;
- optional verified/manual association time, distinct from import time.

A record may have no address, several addresses, or incomplete city/country data.
Preserve useful incomplete records. Do not invent missing fields.
Phone/email normalization must preserve original values and ambiguous region cases.
Do not merge people solely because their names or addresses match.

Shared live location may be reserved in a future schema, but no live-location
collection or covert tracking is part of this release. Unsupported live-data
records must not become trusted presence evidence during import.
